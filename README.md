# sing-box 多协议（hy2/tuic/Anytls/mieru）管理脚本

[![Shell](https://img.shields.io/badge/Shell-POSIX-89E051?logo=gnu-bash&logoColor=white)](https://pubs.opengroup.org/onlinepubs/9699919799/)[![Platform](https://img.shields.io/badge/Platform-Linux-blue)](https://www.kernel.org/)[![License](https://img.shields.io/badge/License-MIT-lightgrey)](./LICENSE)

一个用于快速部署和管理 **sing-box** 多协议服务端的脚本，集成：

- **Hysteria2**
- **TUIC**
- **AnyTLS**
- **Mieru**

适用于 VPS、家宽、NAT 机器、单栈 / 双栈环境。

> **合规提示**：本项目涉及网络代理、流量中转和加密通信，不同国家 / 地区对相关技术的法律与监管要求不同。请确认你对所用服务器和网络拥有合法所有权或明确授权，并遵守当地法律、云服务商 / IDC / ISP 的服务条款。完整内容见 [免责声明与合规提示](#免责声明与合规提示)。

> 脚本使用 POSIX `sh` 编写，可直接用 `sh` / `dash` / `bash` 运行。

## 功能特性

- 一键安装 `sing-box`
- **先检测环境，再让你配置**
  - 自动识别系统、架构、`systemd` / `OpenRC`
  - 自动检测公网 IPv4 / IPv6，并在只有单栈时自动选用对应 IP 栈
- 先选择协议组合，再生成配置（支持任意单协议或组合）
  - Hysteria2 / TUIC / AnyTLS / Mieru
  - 支持多选，例如只装 Hysteria2 + Mieru
- 先选择 IP 栈，再生成配置
  - 仅 IPv4 / 仅 IPv6 / 双栈
  - 节点输出只显示所选栈
- 自动生成证书
- 自动生成节点链接（含 Mieru 的 `mierus://` 链接）
- 支持自定义节点名称前缀（即链接 `#` 后的内容）
- TLS 伪装域名（SNI）
  - 内置多个常见域名
  - 安装时自动测速并选择延迟最低的
  - 支持手动选择或自定义域名
- 支持多条中转线路
  - 本机节点始终直连，独立存在
  - 可额外添加任意多条“中转线路”，每条线路单独配置落地 SOCKS5/HTTP
  - 每条线路有自己的名称、端口和节点链接
  - 添加 / 修改 / 删除线路不影响本机节点
  - 落地机可用同仓库的 `landing.sh` 一键搭建
- 支持菜单管理
  - 重装
  - 卸载
  - 重置端口
  - 重启服务
  - 查看节点
  - 修改协议 / IP 栈
  - 修改节点名称
  - 修改伪装域名
  - 修改中转设置
- 支持 `systemd` / `OpenRC`
- 支持常见 Linux 发行版
- 自动处理基础依赖安装
- 可自定义限速、端口、SNI 等参数

## 快速开始

### 1. 下载脚本

```bash
sh -c "$(curl -fsSL https://raw.githubusercontent.com/WuCaiCaiCai/sbox-easy-single/main/sbox.sh)"
```

或者直接上传脚本到服务器后执行：

```bash
chmod +x sbox.sh
sh sbox.sh
```

### 2. 首次运行

脚本会依次完成以下步骤：

1. 检查并安装基础依赖（仅缺失时）
2. **环境检测**：系统 / 架构 / init 系统 / 公网 IPv4 / 公网 IPv6
3. 选择要安装的协议（可多选）
4. 选择 IP 栈（仅 IPv4 / 仅 IPv6 / 双栈；只有单栈时自动选择）
5. 配置各协议端口
6. 设置本机节点名称前缀（可留空使用默认名称）
7. 测试并选择 TLS 伪装域名（SNI）
8. 下载并安装 `sing-box`（启用 Mieru 时使用 `mbox` 构建）
9. 生成证书
10. 按所选协议与 IP 栈生成配置文件
11. 启动服务
12. 输出本机节点信息

> 安装完成后，可在菜单 `9) 中转线路管理` 中添加任意多条中转线路。

> 脚本不会默认开启全部协议或双栈，协议与 IP 栈都需要手动选择。

## 菜单功能

脚本运行后会进入管理菜单：

```reStructuredText
===== sing-box / Mieru 多协议管理脚本 =====
当前协议：Hysteria2 / TUIC / AnyTLS / Mieru
当前网络：IPv4 + IPv6（双栈）
当前线路：无（仅本机直连节点）
1) 重装（重新选择协议 / IP 栈）
2) 卸载
3) 重置端口（本机节点）
4) 重启服务
5) 查看节点
6) 修改协议 / IP 栈
7) 修改节点名称（本机节点）
8) 修改伪装域名（SNI）
9) 中转线路管理
0) 退出
```

### 1. 重装

重新安装整套环境，包括：

- `sing-box`
- 配置文件
- 服务文件
- 证书
- 节点信息

重装时会重新选择协议与 IP 栈；已添加的中转线路会被清除。

### 2. 卸载

删除：

- `sing-box` 程序（含 `libcronet.so`）
- 配置文件
- 证书文件
- 服务文件

### 3. 重置端口（本机节点）

仅重新生成**本机节点**的端口，并自动重启服务。中转线路的端口需要在菜单 `9) 中转线路管理` 中单独修改。

### 4. 重启服务

仅重启服务，不修改配置。

### 5. 查看节点

重新检测公网 IPv4 / IPv6，并输出：

- 本机节点（始终直连）
- 每条中转线路的节点
- 每条中转线路的上游连接（含密码，仅本机 / 运维查看）

### 6. 修改协议 / IP 栈

在不重装程序的前提下，重新选择协议组合与 IP 栈：

- 新启用的协议会提示输入本机端口；已添加的中转线路也会补问对应的线路端口
- 取消启用的协议会从配置中移除
- 若新组合需要 / 不需要 Mieru，会自动切换 `sing-box` 构建（官方版 / `mbox`）
- 修改后自动重启服务并输出节点

### 7. 修改节点名称（本机节点）

只修改**本机节点**链接 `#` 后的名称前缀，不影响中转线路：

- 回车：保持当前前缀
- 输入 `-`：清除前缀，恢复默认名称
- 输入其他内容：设置为新的前缀

中转线路的名称在菜单 `9) 中转线路管理` 中添加 / 修改线路时单独设置。

### 8. 修改伪装域名（SNI）

重新测速并选择 TLS 伪装域名，随后重新生成证书并重启服务：

- 回车：使用测速最快的域名
- 输入序号：选择对应内置域名
- 输入 `0`：手动输入自定义域名

> 仅影响 Hysteria2 / TUIC / AnyTLS；Mieru 不使用该 SNI。

### 9. 中转线路管理

进入子菜单：

```text
===== 中转线路管理 =====
本机节点：直连（始终保留，不受中转线路影响）
当前线路：2 条
  1) TR   SOCKS5 1.2.3.4:1080
  2) JP   HTTP   5.6.7.8:8080
1) 添加中转线路
2) 修改中转线路
3) 删除中转线路
0) 返回
```

- 可以添加任意多条线路
- 每条线路单独配置名称、落地连接、端口
- 添加 / 修改 / 删除线路不会影响本机节点和其他线路

## 配置说明

脚本只会为**实际选择的协议**生成入站配置，可选：

- **Hysteria2**
- **TUIC**
- **AnyTLS**
- **Mieru**（同时开启 TCP + UDP 两个入站，共用同一端口）

例如只选择 `Hysteria2` 与 `AnyTLS` 时，配置文件中不会出现 TUIC / Mieru 入站。

配置结构：

- **本机节点入站**：始终存在，`route.final` 为 `direct`
- **中转线路入站**：每条线路为每个启用协议生成一组入站，并命中 `route.rules`，走该线路的落地 outbound
- 本机节点与各中转线路使用不同端口，互不影响

默认使用同一套证书，并自动生成对应所需参数。

IP 栈选择对配置的影响：

- 仅 IPv4：监听 `0.0.0.0`，只输出 IPv4 节点
- 仅 IPv6：监听 `::`，只输出 IPv6 节点
- 双栈：监听 `::`，同时输出 IPv4 / IPv6 节点

### 默认路径

```reStructuredText
/usr/local/bin/sing-box
/usr/local/lib/libcronet.so
/etc/sing-box/config.json
/etc/sing-box/state.env
/etc/sing-box/cert.pem
/etc/sing-box/key.pem
/etc/sing-box/info.log
```

## 伪装域名（SNI）

脚本会让 Hysteria2 / TUIC / AnyTLS 的客户端在 TLS 握手中发送一个常见域名的 SNI，并让服务端使用 CN 为该域名的自签证书。

需要明确：

- 这**不是**真正的域名前置（domain fronting），也不会把流量伪装成 HTTP 流量
- 客户端使用 `insecure=1` / `allowInsecure=1`，不会校验证书
- TUIC 本身是 QUIC + TLS 代理协议，DPI 仍可能通过协议特征识别
- SNI 的作用主要是让 TLS ClientHello 看起来更常见

### 自动测速

安装时会并发测试下列域名的 TLS 握手延迟，并默认选择最快的：

- `www.bing.com`
- `www.microsoft.com`
- `www.apple.com`
- `www.cloudflare.com`
- `www.amazon.com`
- `www.github.com`
- `www.tesla.com`
- `www.icloud.com`

可通过环境变量覆盖候选列表：

```bash
export SNI_CANDIDATES="www.bing.com www.apple.com www.example.com"
```

### 自定义

安装时选择 `0` 手动输入，或之后在菜单 `8) 修改伪装域名（SNI）` 中修改。

也可以直接指定，跳过测速：

```bash
export SNI_HOST=www.example.com
```

## 多条中转线路（落地 SOCKS5 / HTTP）

本机节点默认**直连**，并且始终保留：

```text
客户端 ──本机节点──→ 中转机 ─────────────────→ 目标网站（出口 = 中转机）
```

需要额外出口时，在菜单 `9) 中转线路管理` 中添加“中转线路”。每条线路单独配置落地机：

```text
客户端 ──线路 TR──→ 中转机 ──→ TR 落地机 ──→ 目标网站（出口 = TR）
客户端 ──线路 JP──→ 中转机 ──→ JP 落地机 ──→ 目标网站（出口 = JP）
```

可以同时添加多条线路，互不影响，也不会改变本机节点。

### 节点示例

本机节点（安装时生成，始终直连）：

```text
[V4]
...#HY2_V4
...#TUIC_V4
```

中转线路（每条线路一组，名称由你填写，不写死地区）：

```text
[V4 中转 TR]
...#TR_HY2_V4
...#TR_TUIC_V4

[V4 中转 JP]
...#JP_HY2_V4
...#JP_TUIC_V4
```

`TR`、`JP` 只是示例，添加线路时可以填任意名称（如 `TR-Istanbul`、`Line1`）。

### 添加中转线路

菜单 `9) 中转线路管理` → `1) 添加中转线路`，依次配置：

1. **线路名称**：自定义，例如 `TR`、`JP`、`US-West`
2. **落地类型**：SOCKS5 或 HTTP
3. **落地连接**：粘贴落地机提供的链接
4. **线路端口**：为每个已启用协议分配端口（回车随机）

完成后会：

- 生成该线路的入站（与线路名称、端口对应）
- 在 `route.rules` 中把该线路的入站指向自己的落地 outbound
- 重启服务并输出该线路的节点链接

本机节点的配置和链接不会改变。

### 修改 / 删除线路

- `2) 修改中转线路`：选择线路序号，修改名称、落地连接、端口
- `3) 删除中转线路`：删除后其余线路自动前移，不影响本机节点

删除或修改线路只影响该线路，不影响其他线路和本机节点。删除线路后，本机防火墙中已有的端口放行规则可能保留，需要时可手动清理。

### 端口

- 本机节点端口：安装时配置，或在菜单 `3) 重置端口（本机节点）` 中重置
- 每条线路的端口：添加 / 修改该线路时单独配置
- 脚本会自动避免与本机节点、其他线路的端口冲突

### 落地连接

落地机可以用同仓库的 [`landing.sh`](./landing.sh) 一键搭建，输出：

```text
socks5://user:pass@1.2.3.4:1080
http://user:pass@1.2.3.4:8080
```

复制后粘贴到“添加中转线路”的落地连接即可。

### 注意事项

- 落地连接（`socks5://...` / `http://...`）包含账号密码，只给中转机 / 运维使用，**不要发给客户端**
- 客户端只使用“本机节点”和“中转线路”的节点链接
- SOCKS5 落地支持 TCP + UDP；HTTP 落地只支持 TCP
- 中转机 → 落地机是明文代理，跨公网建议配合私有网络 / WireGuard，并限制落地来源 IP
- “查看节点”会同时列出本机节点、每条中转线路，以及对应的上游连接

## Mieru 说明

官方 `sing-box` **不包含** Mieru 入站，因此启用 Mieru 时脚本会自动安装 [enfein/mbox](https://github.com/enfein/mbox)（`sing-box` 的 Mieru 分支，产物与官方同名同结构）。

- 一个进程、一套配置、一套服务文件即可同时跑 Hysteria2 / TUIC / AnyTLS / Mieru
- 切换协议组合时，脚本会自动在**官方版**与 **mbox 版**之间切换二进制
- 端口同时用于 TCP 与 UDP，因此会自动放行两个协议

Mieru 支持以下客户端：

- 官方客户端 [enfein/mieru](https://github.com/enfein/mieru)
- `mihomo` / `clash.meta`（`type: mieru`）

## 环境变量

你可以在运行脚本前自定义部分参数：

### 自定义 SNI / 证书域名

```bash
export SNI_HOST=www.bing.com
```

设置后会跳过安装时的自动测速，直接使用该域名。候选列表也可以用环境变量覆盖：

```bash
export SNI_CANDIDATES="www.bing.com www.apple.com www.example.com"
```

### 自定义 Hysteria2 限速

```bash
export HY2_UP_MBPS=100
export HY2_DOWN_MBPS=100
```

### 自定义节点名称前缀

```bash
export NODE_PREFIX=HK
```

首次安装时会作为默认值出现，之后也可以在菜单 `7) 修改节点名称` 中修改。

> `NODE_PREFIX` 仅控制本机节点；中转线路的名称在菜单 `9) 中转线路管理` 中添加 / 修改线路时单独设置。

> 端口在安装时通过交互输入（留空随机），暂不支持环境变量预设。

## 节点输出

安装完成后，脚本会输出**本机节点**（始终直连）：

- `HY2_V4` / `HY2_V6`
- `TUIC_V4` / `TUIC_V6`
- `AnyTLS_V4` / `AnyTLS_V6`
- `Mieru_V4` / `Mieru_V6`

添加中转线路后，每条线路会额外输出一组节点，例如：

```text
[V4]
...#HY2_V4

[V4 中转 TR]
...#TR_HY2_V4

[V4 中转 JP]
...#JP_HY2_V4
```

例如：

- 只选 Hysteria2 + Mieru、仅 IPv4：输出对应的 IPv4 本机节点
- 选择双栈但机器没有可用 IPv6：只会输出 IPv4 节点
- 本机 + 2 条线路 + 双栈：会输出本机 V4/V6、线路 1 V4/V6、线路 2 V4/V6

本机节点名称由“节点名称前缀”控制，例如前缀 `HK` 时是 `HK_HY2_V4`；中转线路名称由线路自己的名称控制，例如 `TR_HY2_V4`、`JP_TUIC_V4`。`#` 后的名称只影响客户端显示，不影响连接。

TUIC 链接格式为 `tuic://UUID:密码@地址:端口?...`（UUID 与密码之间使用明文冒号）。

Mieru 链接示例：

```text
mierus://用户名:密码@节点地址?port=端口&protocol=TCP&port=端口&protocol=UDP&profile=default#节点名称
```

可直接用官方客户端导入：

```bash
mieru import config "mierus://..."
```

`mihomo` / `clash.meta` 参考写法：

```yaml
- name: Mieru
  type: mieru
  server: 节点地址
  port: 端口
  username: 用户名
  password: 密码
  transport: TCP
  udp: true
```

## 常见问题

### 1. 为什么没有输出 IPv6 节点？

可能原因：

- 安装时选择的是“仅 IPv4”
- 服务器本身没有可用 IPv6 出口
- 云厂商未分配 IPv6
- 防火墙或安全组未放行对应端口
- IPv6 探测源访问失败

如果选择的是“仅 IPv6”，可执行 `curl -6 ip.sb` 检查本机 IPv6 是否可用。

------

### 2. 为什么客户端无法连接？

请检查：

- 云服务器安全组是否放行端口
- 本机防火墙是否放行端口（Mieru 需要同时放行 TCP 与 UDP）
- 节点地址是否正确
- 客户端是否开启 `allowInsecure` / `insecure`
- SNI 是否与证书一致

------

### 3. NAT 机器可以用吗？

可以。脚本适用于只要能访问外网的 NAT 环境，并会尝试自动探测公网 IPv4 / IPv6。

------

### 4. sing-box 无法执行（退出码 137 / 9）？

`137` / `9` 表示进程被 `SIGKILL` 杀掉，常见原因：

- 内存不足（OOM）
- 安全策略 / cgroup 限制

可检查：

```bash
cat /sys/fs/cgroup/memory.events
cat /sys/fs/cgroup/memory.max
dmesg | tail
```

### 5. 如何查看服务状态？

#### systemd

```bash
systemctl status sing-box
journalctl -u sing-box -e --no-pager
```

#### OpenRC

```bash
rc-service sing-box status
```
